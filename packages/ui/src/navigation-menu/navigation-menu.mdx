# NavigationMenu

Site navigation with hover/click flyout panels that morph between triggers. A compound component on Base UI's `NavigationMenu`: the root owns the shared flyout, you compose the parts.

```tsx
import { NavigationMenu } from '@core/ui/navigation-menu/navigation-menu'

<NavigationMenu>
  <NavigationMenu.List>
    <NavigationMenu.Item>
      <NavigationMenu.Trigger>Work</NavigationMenu.Trigger>
      <NavigationMenu.Content>
        <NavigationMenu.ContentLink href="/shiftboard" title="Shiftboard" meta="2024" />
      </NavigationMenu.Content>
    </NavigationMenu.Item>
    <NavigationMenu.Item>
      <NavigationMenu.Link href="/cv">CV</NavigationMenu.Link>
    </NavigationMenu.Item>
  </NavigationMenu.List>
</NavigationMenu>
```

## Parts

- `NavigationMenu`: root `<nav>` (labelled "Main" by default) plus the flyout. Accepts Base UI `delay` / `closeDelay`.
- `.List` / `.Item`: the pill bar and its entries.
- `.Trigger`: opens a `Content` panel; renders its own chevron.
- `.Content`: panel body. Give inner content a fixed width so the morph has a target size.
- `.Link`: top-level link without a panel. Use `render` for a router link.
- `.ContentLink`: row link inside a panel with `title`, optional `description` and `meta`.

## Accessibility

- Hover opens the panel, click and keyboard work too. Arrow keys move between triggers, Down enters the panel, Escape closes.
- Triggers expose `aria-expanded`; give the root a more specific `aria-label` if there are several navs on the page.

## Don't

- Don't pass `className`; styling comes from the recipes.
- Don't put non-navigation content (forms, actions) in a panel.
- Don't use `Content` without a `Trigger` in the same `Item`.
